Service endpoints are not private endpoints: MongoDB and OpenAI retain their public endpoint names and IP addresses, with subnet-based firewall enforcement. Their `publicNetworkAccess` must remain `Enabled` for this design. Use deny-by-default network rules with no public IP exceptions; do not set a global public-access bypass to make a failed test pass. Blob keeps `publicNetworkAccess=Disabled` and its existing identity-based access.

Enabling `Microsoft.CognitiveServices` also reroutes Speech traffic. Microsoft requires an explicit Speech subnet rule even if that resource previously allowed public traffic. Azure validated and accepted this rule on the **existing F0** Speech account: no upgrade or private endpoint is needed. The generator must set `DvarTorahAudio__SpeechServiceUri=https://askarabbi-speech-prod.cognitiveservices.azure.com/`. The narrator uses that custom host with managed-identity authorization; its regional host times out in this network configuration. Keep Speech public-network access Enabled with default Deny and only the new subnet allowed. See [Speech service endpoints](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-service-vnet-service-endpoint).

The environment provides public API ingress without a separate gateway. This migration adds no NAT Gateway, VPN Gateway, Application Gateway, Azure Firewall, private endpoint, or private DNS zone. It does not promise zero Azure charges: ordinary runtime, network transfer, logging, and existing service usage continue. Do not retain duplicate runtime environments for a rollback window after the new system passes cutover checks.

## Operational access after isolation

Azure management-plane operations such as deployments, resource configuration, and role assignments remain separate from service data-plane access. A public laptop's MongoDB client or direct OpenAI inference/corpus publisher is outside the approved service-endpoint subnet, even if its Azure identity has a role. Run approved maintenance from a controlled workload on the allowed subnet; a VPN connection by itself does not automatically acquire that subnet's service-endpoint identity. Do not add a gateway, administrator public IP exception, or new allowed subnet without separate approval.
